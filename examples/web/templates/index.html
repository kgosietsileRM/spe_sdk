INFO VIEW

Monitoring, live camera selection, analytics, and session review.

01 · APPLICATION OVERVIEW

A single-feed traffic operations workflow

The camera wall reads sources from examples/assets/link.json. Operators select one of six YouTube feeds or the recorded sample, choose a lane preset, and start monitoring.

LIVE FEEDS

YouTube links are resolved to a readable stream. The selected camera is analyzed; other wall tiles remain still previews.

REVIEW

Live sessions run until stopped and keep a rolling replay window. Finite clips can be sampled and exported as JSON reports.

04 · APPLICATION LOGIC

What FlowTraffic adds around SPE

01

Camera operations

Source selection, YouTube stream resolution, live-wall previews, sessions, and replay.

02

Traffic telemetry

Lane aggregation for occupancy, queue length, crossings, congestion, and relative speed.

03

Incident rules

Application policies detect stopped vehicles, queue buildup, network congestion, and lane imbalance.

04

Response guidance

Advisory states and suggested actions are derived from the incident and telemetry history.

Detection modes: Local mode uses a lightweight OpenCV motion detector for demonstration. It is not a trained vehicle-classification model. Server mode sends frames through SPEClient to the configured SPE engine.

05 · CODE WALKTHROUGH

How a frame becomes telemetry

The core loop tracks detections first, spatializes the tracked objects, and then updates occupancy. The web layer aggregates those results into traffic events and advisories.

detections = detector.detect(frame, frame_index, timestamp)
tracked = tracker.update(detections, timestamp)["detections"]
spatial = engine.spatialize_result(
    {"detections": tracked}
)["detections"]
occupancy_snapshot = occupancy.update(spatial, timestamp)
lane_snapshot = build_lane_telemetry(spatial, counters)
incidents = detect_incidents(history, policy)
